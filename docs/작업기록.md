### 2. 긴 문서를 셸 heredoc으로 쓰려다 실패함

| 항목 | 내용 |
| --- | --- |
| 무엇이 틀렸는지 | `docs/PRD.md`를 셸의 heredoc(`cat > ... <<EOF`)으로 쓰려 했다. 문서 안에 작은따옴표(`'기획자','웹 프로그래머'`)가 많아 셸이 명령을 끝까지 읽지 못하고 `unexpected EOF while looking for matching '` 오류를 냈다 |
| 어떻게 알았는지 | 명령을 실행했는데 파일이 만들어지지 않고 위 오류가 나왔다 |
| 고친 커밋 번호 | `c1f4d82` (파일 쓰기 도구로 바꿔서 작성함. 커밋 전이라 잘못된 파일은 저장소에 들어가지 않았다) |

### 3. `python -m pip` 이 동작하지 않음

| 항목 | 내용 |
| --- | --- |
| 무엇이 틀렸는지 | `python -m pip --version` 을 실행했더니 `Python` 한 단어만 찍고 종료 코드 49로 끝났다. PATH의 `python` 이 Windows 앱 스토어용 가짜 실행 파일(`WindowsApps\python.exe`)을 먼저 가리켜서 생긴 문제였다 |
| 어떻게 알았는지 | `where python` 으로 경로가 두 개(`WindowsApps`와 실제 설치 폴더) 나오는 것을 보고, 실제 설치 경로로 직접 실행해 보니 정상 동작했다 |
| 고친 커밋 번호 | 커밋 없음 (코드 문제가 아니라 실행 방법 문제. 이후로는 `.venv\Scripts\python.exe` 를 직접 쓴다) |

### 4. `db.py` 를 고친 뒤 앱 서버를 다시 시작하지 않아 앱이 죽었음

| 항목 | 내용 |
| --- | --- |
| 무엇이 틀렸는지 | 3단계에서 `db.py` 에 `execute_many` 함수를 새로 넣었는데, 이미 돌고 있던 Streamlit 서버는 예전 `db.py` 를 기억하고 있었다. 그래서 명단 올리기 단추를 누르면 `AttributeError: module 'db' has no attribute 'execute_many'` 가 났다 |
| 어떻게 알았는지 | 브라우저에서 "명단으로 처음 상태 만들기" 단추를 눌렀는데 팀이 만들어지지 않았다. 화면과 서버 기록을 읽어 보니 위 오류가 있었다 |
| 고친 커밋 번호 | 커밋 없음 (코드가 아니라 서버를 다시 시작해서 해결). **배운 점: 앱이 `import` 하는 파일(`db.py`, `auth.py`, `roster.py`)을 고치면 Streamlit 서버를 다시 시작해야 한다.** 화면만 새로 고치면 예전 코드가 그대로 돈다 |

### 5. 오류가 나면 화면에 오류 추적(Traceback)이 그대로 보였음

| 항목 | 내용 |
| --- | --- |
| 무엇이 틀렸는지 | 위 4번 오류가 났을 때, 화면에 `AttributeError ... Traceback ... File "streamlit_app.py", line 224` 같은 내용이 그대로 나왔다. 이러면 채점 프로그램이 `result` 안내를 못 읽고 그 자리에서 멈춘다(공고 6.2절 6항, 감점 15번과 이어짐) |
| 어떻게 알았는지 | 4번을 찾는 과정에서 브라우저 화면에 오류 추적이 보이는 것을 직접 봤다 |
| 고친 커밋 번호 | `e0c1d8a` — 명단 올리기 처리에 모든 오류를 받아 내는 `except Exception` 을 넣고, 화면에는 `막힘: 명단을 처리하지 못함` 만 보여 주고 자세한 내용은 서버 기록에만 남기게 고쳤다. 다시 시험했을 때 화면에 `Traceback` 이 없는 것을 확인했다 |

### 6. 묶음 처리(트랜잭션) 안에서 자리 충돌이 나면 뒤의 작업이 모두 실패했음

| 항목 | 내용 |
| --- | --- |
| 무엇이 틀렸는지 | `teamflow._place_member` 는 1번 자리부터 넣어 보고 이미 찼으면 다음 자리를 시도하는 방식이다. 그런데 배정 확정처럼 여러 명을 한 묶음으로 넣을 때는, 자리가 겹쳐 한 번 실패하면 **묶음 전체가 중단**되어 그 뒤 모든 질의가 `InFailedSqlTransaction` 오류를 냈다 |
| 어떻게 알았는지 | 6단계 검사를 돌렸을 때 "확정" 항목에서 `psycopg.errors.InFailedSqlTransaction: current transaction is aborted` 오류가 나며 멈췄다 |
| 고친 커밋 번호 | `a2c3934` — 자리에 넣는 시도를 **저장점(savepoint)** 안에서 하도록 고쳤다. 실패해도 그 시도만 되돌려지고 묶음은 이어진다. 다시 돌려서 8명 확정이 통과하는 것을 확인했다 |

### 7. `.env` 의 닫는 따옴표가 빠진 것을 해석기가 못 걸러 모든 AI 호출이 401 로 실패했음

| 항목 | 내용 |
| --- | --- |
| 무엇이 틀렸는지 | `.env` 의 `OPENROUTER_API_KEY` 줄에 **닫는 따옴표가 빠져** 있었다. 내가 만든 `db._from_env_file` 은 "앞뒤가 모두 따옴표일 때만" 따옴표를 떼어 내게 되어 있어서, 앞의 따옴표 한 개가 키 값에 그대로 섞여 들어갔다. 그래서 오픈라우터가 모든 호출을 `HTTP 401` 로 거부했다 |
| 어떻게 알았는지 | 실제 모델 3개가 전부 `HTTP 401` 로 실패했다. 키 문제인지 코드 문제인지 가리려고 **값은 출력하지 않고** 길이·접두사·따옴표 개수만 찍어 봤더니, 길이가 74자(정상 73자)이고 따옴표가 1개 섞여 있었다. `.env` 각 줄의 따옴표 개수를 세어 보니 1줄만 1개였다 |
| 고친 커밋 번호 | `a2c3934` — 한쪽 따옴표만 있어도 떼어 내도록 고쳤다. 고친 뒤 오픈라우터 키 확인이 `HTTP 200` 으로 바뀌었다 |

### 9. 3장 1번 기능(다른 사람의 변경 보기)을 아예 빠뜨렸음

| 항목 | 내용 |

| 무엇이 틀렸는지 | 4단계를 "다 끝났다"고 보고 5단계로 넘어갔는데, 3장 표의 1번 기능(다른 사람의 변경 보기, 어려운 해결 1점)을 만들지 않았다. 새로 고침 단추도 없고 자동 갱신도 없어서, 다른 학생의 지원이 내 화면에 아예 나타나지 않았다. 이 상태로 채점을 받으면 **채점 프로그램이 지원·투표를 못 보고 그 자리에서 멈춘다** |

### 10. DB 연결 하나를 모든 사용자가 함께 써서, 한 사람의 실패가 남의 화면을 깨뜨렸음

| 항목 | 내용 |
| --- | --- |
| 무엇이 틀렸는지 | 공고 4.2절의 "연결은 한 번만 만들고 다시 써라" 를 **연결을 딱 하나만 만들어 모두가 공유** 하는 것으로 만들었다. 그런데 화면이 5초마다 갱신되므로 학생 여러 명이 접속하면 질의가 한꺼번에 몰린다. 그 결과 (1) 한 사람의 묶음 처리 도중에 다른 사람의 질의가 끼어들어 `InFailedSqlTransaction` 오류가 번졌고, (2) 질의가 줄을 서느라 화면 갱신이 몇 초씩 늦어져 투표 단추가 제때 나타나지 않았다 |
| 어떻게 알았는지 | 자동 테스트에서 투표 단추를 못 찾아 계속 "막힘" 이 나왔다. 앱만 따로 열어 보면 잘 되는데 테스트에서만 안 되는 것이 이상해서 **서버 기록**을 읽었더니 `psycopg.errors.InFailedSqlTransaction: current transaction is aborted` 가 수십 번 쌓여 있었다. 자물쇠로 한 명씩 쓰게 고쳐 보니 오류는 사라졌지만, 이번에는 질의 10번이 0.8초에서 2.3초로 늘어 화면이 더 늦어졌다 |
| 고친 커밋 번호 | `3cca978` — 연결 풀(`psycopg_pool`)로 바꿨다. 연결 2~10개를 미리 만들어 두고 돌려 쓴다. 질의마다 새로 연결하는 것이 아니므로 공고가 경고한 느려짐은 생기지 않는다. 풀 연결을 autocommit 으로 두어 질의 하나마다 묶음을 여닫는 왕복도 없앴다. 고친 뒤 질의 10번이 **0.756초**로 돌아왔고, 자동 테스트의 투표 단추 문제도 모두 사라졌다 |
| 왜 중요한지 | 채점 때는 가상 학생 8~16명의 브라우저가 동시에 열린다. 이 문제를 못 찾았으면 채점 중에 화면이 깨졌을 것이다 |

### 11. (테스트 프로그램) 자동 갱신과 클릭이 겹쳐 눌림이 사라졌음

| 항목 | 내용 |
| --- | --- |
| 무엇이 틀렸는지 | 테스트가 단추를 찾아 두고 눌렀는데, 그 사이 앱이 5초 자동 갱신으로 화면을 다시 그리면 눌림이 사라졌다. 또 관리자 페이지를 `reload()` 했더니 **로그인이 풀려서** 그 뒤 관리자 동작이 모두 실패했다. AI 배정은 100초가 걸리는데 기다리는 시간을 25초로 잘라 두어 "막힘" 으로 잘못 적혔다 |
| 어떻게 알았는지 | 테스트 결과 표에서 2·4·5단계가 "막힘" 으로 나왔지만, 같은 상황을 브라우저로 직접 해 보면 정상이었다. 앱이 아니라 테스트가 틀렸다는 뜻이었다 |
| 고친 커밋 번호 | `3cca978` — (1) 요소를 미리 붙잡지 않고 로케이터로 그때그때 다시 찾게 했다, (2) 조용한 순간을 기다린 뒤 누르고 "눌린 증거"(안내가 바뀜 또는 단추가 사라짐)를 확인하게 했다, (3) `reload()` 를 없앴다, (4) AI 배정은 최대 7분까지 기다리게 했다 |
